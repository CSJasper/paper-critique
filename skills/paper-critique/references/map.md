# map: 주제 지도 만들기

주제 하나를 읽기 전에 사용자 예측, 후보 풀, 주제 수준 초안을 이 순서로 만든다. 어떤 논문을 skim할지는 사용자가 고른다.

## 상태

1. 주제 파일은 `topics/<slug>.md` 하나이고 `templates/topic.md`를 쓴다. 별도 상태 파일은 없다.
2. 단계마다 주제 파일에 바로 기록하고 frontmatter `next`를 갱신한다. 중단은 SKILL.md 절대 규칙 5를 따른다.

## 1. 시작

0. 인자가 논문 리스트면 7절을 따른다. 리스트인지 가리는 규칙은 7.1에 있다. 이 절의 1–2와 2–6절은 인자가 주제일 때의 흐름이다.
1. `[주제]`는 slug다. 사용자가 준 주제가 `topics/`의 파일 이름과 정확히 맞지 않으면 Claude가 slug를 하나 제안하고, 사용자가 확인하면 그 slug를 알려 준다. 이후 `skim`·`checkpoint`·`read`에는 이 slug를 쓴다.
2. `topics/<slug>.md`가 있으면 `next`부터 이어간다. 없으면 `templates/topic.md`로 만들고 `slug`, `created`, `status: active`를 채운다.

## 2. 사용자 예측

1. 먼저 사용자가 이 주제에 대해 아는 것과 예상 쟁점을 쓴다. Claude는 그 전에 후보·계보·쟁점을 보여주지 않는다.
2. 사용자 원문을 `## 내 예측`에 그대로 저장한다. 저장한 뒤에는 고치지 않는다.

## 3. 후보 풀

1. survey 논문과 WebSearch 결과를 근거로 후보 논문을 대략 15–30편 모은다. 찾은 순서대로 `## 후보 풀`에 한 줄씩 적는다.
2. 후보 줄은 제목 · 연도 · 링크 · 찾은 출처만 쓴다. 순위, "꼭 읽을 것", 추천 표시, 개별 논문의 주장·장단점은 쓰지 않는다.
3. 사용자가 예측에서 이름을 든 논문이나 `papers/`에 이미 있는 PDF도 후보 풀에 넣을 수 있다. 이때 출처 칸에 `사용자 예측` 또는 `papers/`를 쓴다.

## 4. 계보·쟁점·열린 문제 초안

1. `## 계보·쟁점·열린 문제 (초안)`에 이 주제의 계보, 쟁점, 열린 문제를 쓴다.
2. 초안은 주제 수준으로만 쓴다. 개별 후보 논문의 주장·강점·약점을 평가하지 않는다. "이번에 찾은 자료 범위 안에서"라는 단서와 출처를 달고, 검색으로 확인하지 않고 기억에만 기댄 주장은 [추측]으로 표시한다.

## 5. skim 대상 고르기

1. skim할 논문은 사용자가 후보 풀에서 고른다. Claude는 어떤 후보를 고르라고 권하지 않는다.
2. 사용자가 고른 항목을 주제 `next`에 적는다. skim은 `references/skim.md`를 따른다.
3. 사용자가 후보 풀에 없는 논문을 가져와 skim할 수도 있다. 그 논문은 출처 칸에 `사용자 추가`를 써서 후보 풀 끝에 덧붙인다.

## 6. 전환으로 만든 주제

1. checkpoint에서 전환해 만든 주제(`from_topic`이 있는 파일)는 원래 주제와 달라진 부분만 채운다.
2. 순서는 2–3과 같다. 달라진 부분에 대한 사용자 예측을 먼저 받고, 그다음 후보를 보강한다.
3. 원래 주제의 후보 풀은 복사하지 않는다. 새 파일 `## 후보 풀` 첫 줄에 원래 주제 파일(`[[<원래 slug>]]`)의 후보 풀을 가리키는 링크를 쓰고, 그 아래에는 새로 찾은 후보만 적는다.
4. 새 주제의 `## 기록`은 빈 채로 시작한다. checkpoint 집계는 새 파일의 `## 기록` 처음부터 센다.

## 7. 논문 리스트로 시작

`map <논문 리스트>`는 리스트를 씨앗으로 삼아 지도를 만든다. 주어진 논문에서 출발해 주변 논문을 검색으로 보탠다.

### 7.1 입력 인식

1. 항목 하나는 `papers/`의 PDF 경로, arXiv 링크나 ID, 논문 제목 중 무엇이든 된다. 섞어 써도 된다. 항목은 줄바꿈이나 쉼표로 나눈다.
2. 인자에 PDF 경로, 링크, arXiv ID가 하나라도 있거나 항목이 둘 이상이면 논문 리스트로 본다.
3. 제목 하나만 있어 주제 이름인지 논문 제목인지 애매하면 어느 쪽인지 한 번 묻는다.
4. 제목만 준 논문은 검색으로 원문 링크를 찾는다. 찾지 못하면 그 논문의 후보 줄 링크 칸에 `링크 못 찾음`을 쓴다.

### 7.2 순서 (새 주제)

순서를 바꾸지 않는다. 단계마다 주제 파일에 바로 기록하고 `next`를 갱신한다.

1. 목록 정리만 보여 준다. 항목마다 제목 · 연도 · 링크(또는 경로)만 쓴다. 논문 내용 요약이나 "이 논문들의 공통 주제"는 말하지 않는다.
2. slug를 정한다. Claude는 논문 제목만 보고 중립적인 이름을 하나 제안하고, 공통 주제 분석을 덧붙이지 않는다. 사용자가 직접 이름을 줄 수도 있다. 확인한 slug의 주제 파일이 이미 있으면 7.3을 따른다.
3. 주제 파일을 `templates/topic.md`로 만든다. 그다음 2절대로 사용자 예측을 받는다. 리스트로 시작했으면 묶은 이유와 궁금한 것도 함께 쓰게 한다.
4. 후보 풀은 주어진 논문을 맨 위에 출처 `사용자 지정`으로 먼저 적는다. 그 아래에 주어진 논문이 인용하거나 인용받는 논문, 같은 문제를 다루는 논문을 검색으로 보태 합쳐 대략 15–30편을 만든다. 후보 줄 규칙은 3절과 같다.
5. 계보·쟁점·열린 문제 초안과 skim 대상 고르기는 4–5절과 같다.

### 7.3 이미 있는 주제에 더하기

1. 확인한 slug의 `topics/<slug>.md`가 이미 있으면 새 주제를 만들지 않는다.
2. 주어진 논문을 `## 후보 풀` 끝에 출처 `사용자 추가`로 덧붙인다. 이미 후보 풀에 있는 논문은 다시 적지 않는다.
3. `## 내 예측`과 초안은 고치지 않는다. 검색 보강도 하지 않는다.
4. 덧붙인 논문을 알려 주고 skim할 논문은 사용자가 고른다(5절).
