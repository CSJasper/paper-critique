# checkpoint: 계속 / 전환 / 접기

일정 양을 읽을 때마다 이 주제를 계속할지, 방향을 바꿀지, 접을지 사용자가 판단한다.

## 1. `## 기록` 문법

1. 주제 파일 `## 기록`은 append-only다. 한 줄 문법은 `templates/topic.md`와 같다.
   `- YYYY-MM-DD · <skim|deep 완료|checkpoint 제안|checkpoint 제안 거절|checkpoint: <계속|전환|접기>> · [[note]]`
2. `[[note]]`는 `skim` 줄과 `deep 완료` 줄에만 쓴다.
3. **기준선**은 마지막 `checkpoint:` 줄과 마지막 `checkpoint 제안 거절` 줄 중 나중 줄이다. 답을 받지 못한 `checkpoint 제안` 줄은 기준선이 아니다. 기준선이 없으면 `## 기록` 처음부터 센다.

## 2. 트리거

1. 한 주제에서 기준선 이후 skim 판정 8편 또는 deep(read 완료) 1편 중 먼저 오는 쪽에서 Claude가 checkpoint를 한 번 제안한다. 사용자는 언제든 직접 부를 수 있다.
2. 제안할 때 `checkpoint 제안` 줄을 쓴다. 기준선 이후에 답을 받지 못한 `checkpoint 제안` 줄이 있으면 skim을 마칠 때마다 다시 제안하지 않는다. 다음에 그 주제로 들어올 때 한 번만 상기시킨다.
3. 주제 `status`가 `paused`·`dropped`·`pivoted`이면 제안하지 않는다.
4. 거절하면 "checkpoint 제안 거절" 줄을 쓰고, 그 줄 이후로 다시 skim 8편 또는 deep 1편이 쌓일 때까지 묻지 않는다.

## 3. 흐름

1. `[주제]` 없이 부르면 `status: active` 주제가 하나뿐일 때 그 주제로 한다. 아니면 주제 목록을 보여 주고 어느 주제인지 묻는다.
2. 먼저 판단 재료를 평가 없이 나열한다: `## 내 예측` 원문, gap-log에서 `주제` 열이 이 주제인 항목, `## 판정 보정 기록`, 이 주제의 skim·deep 노트 수(노트 `topics` 기준). 모두 사용자 자신의 기록이므로 먼저 보여 줘도 절대 규칙 1에 어긋나지 않는다.
3. 사용자가 `계속 / 전환 / 접기` 중 하나와 근거를 쓴다.
4. Claude가 사용자 판단을 공격한다. 근거 위치를 단다.
5. 결정은 사용자가 한다. `checkpoint: <결정>` 줄을 쓴다.

## 4. 접기

1. 주제 파일을 `status: dropped`로 바꾼다.
2. 다시 열 조건을 사용자에게 따로 묻는다. `## 접기·전환`에 접는 이유와 다시 열 조건을 사용자 말 그대로 한 줄로 옮긴다. Claude가 문장을 지어 넣지 않는다.
3. 노트와 gap-log는 고치지 않는다.

## 5. 전환

1. 새 `topics/<new-slug>.md`를 `templates/topic.md`로 만들고 `from_topic`에 원래 slug를 적는다.
2. 새 주제로 이어 쓸 노트는 사용자가 고른다. 고른 노트의 `topics`에 새 slug를 추가하고, 새 파일 `## 노트`에 링크를 덧붙인다.
3. 원래 주제 파일을 `status: pivoted`로 바꾸고 `## 접기·전환`에 새 slug를 적는다.
4. 새 주제의 지도는 `references/map.md`의 "전환으로 만든 주제"를 따른다.

## 6. 판정 보정 기록

1. skim 판정이 나중에 바뀐 경우에만 `## 판정 보정 기록`에 한 줄 쓴다: 날짜 · 노트 · 원래 판정 → 바뀐 판정 · 이유(사용자 말).
2. 예: `drop`·`done` 판정 노트를 승격할 때, 다시 skim해서 판정이 바뀔 때, `deep`으로 읽어 보니 가치가 낮았다고 사용자가 말할 때.
3. 이 줄은 노트 `topics`에 있는 주제 파일마다 쓴다. `topics`가 없으면 쓰지 않는다.
4. 승격으로 바뀐 경우 `skim_verdict`는 원래 값으로 두고, 판정 칸은 `<원래 판정> → deep(승격)`으로 쓴다. 이유는 사용자 메시지에 이미 있으면 그 말을 그대로 적고, 없으면 한 번 묻는다.
5. skim 흐름 5단계에서 반론을 듣고 같은 세션에 바꾼 최종 판정은 판정 보정이 아니다(`references/skim.md`).
6. 확신도나 판정 일치율은 모으지 않는다.

## 7. 범위 밖

1. 주제끼리 잇는 기능은 없다. 주제를 넘나드는 연결은 synth가 찾는다.
