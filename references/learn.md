# learn: 개념 하나를 한 단계씩

[LearnHarness](https://github.com/amosblomqvist/learnharness)(AGPL-3.0)의 교수 이론을 개념 단위 학습에 맞게 재구성했다. 문장은 새로 썼고 코드는 가져오지 않았다.

## 범위

1. 한 번의 learn은 개념 하나만 다룬다. 논문 전체를 미리 가르치지 않는다.
2. learn 안에서 새 learn을 열거나 제안하지 않는다. 선행 개념이 필요하면 현재 개념의 한 단계로 가르치고, 개념 노트의 `## 선행 단계`에 평문 목록으로 적는다. 선행 개념 노트는 필요할 때만 `learn_state: none`으로 만든다.

## 이론의 뼈대

- 학습은 목표 명제가 당연하게 느껴지는 상태다. 외워서 말할 수 있는 것은 아직 배운 게 아니다. 당연하다는 것은 더 근본적인 사실이 나중에 그것을 뒤집을 일이 없고, 다른 사실과 연결돼 있다는 뜻이다.
- 지식은 구조다. 명제가 노드, 추론 단계가 엣지다. 연결 없는 명제는 쉽게 사라진다.
- 가르치기는 명제를 올바른 순서로 한 추론 단계씩 놓는 일이다. 각 단계가 이미 당연한 것에 한 단계로 붙으므로 그대로 자리 잡고, 오류도 바로 그 위치에서 드러난다.

## 시작

1. `concepts/`에서 `name`과 `aliases`로 같은 개념 노트를 찾는다. 없으면 `templates/concept.md`로 만든다.
2. `learn_state`가 `in-progress`나 `paused`면 `learn_next`와 `## 선행 단계`를 먼저 읽는다. in-progress면 그 지점부터 이어간다. paused면 `learn_state`를 `in-progress`로 바꾸고 `learn_next`부터 이어간다. `none`, `skipped`, `done`이면 처음부터 시작한다. `learn_state: in-progress`로 바꾸고 `learn_next`를 새로 쓴다.
3. 선행지식 확인 질문은 최대 2개다. 답과 함께 확신도를 받고 아래 표로 읽는다. "모름"은 오답이 아니라 빈칸이다.

| | 확신 높음 | 확신 낮음 |
|---|---|---|
| 맞음 | 확실한 지식. 그 위에서 시작 | 취약하거나 찍음. 짧게 다지고 간다 |
| 틀림 | 굳어진 오개념. 그 단계를 먼저 고친다 | 경계 근처 빈칸. 작은 교정으로 충분 |

## 가르치기

### 두 원칙
1. **무조건적 참 먼저.** 단서 없이 받아들일 수 있는 보편 진술이나 진짜 정의를 먼저 둔다. 쌓기 전에 그 기초가 정말 당연하게 느껴지는지 짧게 확인한다.
2. **"내가 이걸 어떻게 발견할 수 있었을까?"** 임의적으로 느껴지는 사실은 남지 않는다. 왜 이 문제가 생기는지, 왜 하필 이 식과 이 변형인지 동기부터 단다.

### 한 단계의 규칙
1. 한 단계에는 사실 하나만 담는다. 두 번 설명해야 들어가면 두 단계다.
2. 단계마다 가장 명확한 형태로 쓴다. 기초는 그냥 단언하는 편이 나을 때가 많다.
3. 메타 해설("이제 X를 확립하고 Y와 연결하겠다")을 쓰지 않는다. 사용자가 내용 대신 수업 구조를 처리하게 된다.
4. 이해를 더하지 않는 문장은 쓰지 않는다.

### 한 단위: predict → teach → check
1. **predict**: 지금 이해로 안 풀리는 지점을 짚고 다음 단계를 추측하게 한다. 틀려도 된다. "모르겠다"는 정당한 답이다. 추측을 강요하지 말고 바로 teach로 간다. 정리 턴과 수리 턴에서는 생략할 수 있다.
2. **teach**: 추측이 있으면 먼저 그 추측을 다룬 뒤 한 단계만 가르친다. 사용자가 추론할 수 있으면 질문으로, 아니면 설명으로 간다.
3. **check**: 방금 단계를 새 사례에 적용하는 문제를 낸다. 방금 문장을 따라 말하게 하지 않는다. 세션에서 다룬 것만으로 추론해 답할 수 있어야 한다. 오답이 어떤 잘못된 모델인지 드러나게 만든다. 답과 함께 확신도와 생각을 받는다.
4. 답보다 생각을 1차 데이터로 읽는다. 혼란스러운 모델 위에서 나온 정답은 경고 신호이고, 건전한 추론에서 나온 오답은 진전이다.
5. 틀리면 진단 → 수리 → 재check. `pass`와 `pass(hint)`의 구분은 `templates/concept.md` 상태 규칙을 따른다.
6. 같은 단계에서 진단 → 수리 → 재check가 3회 실패하면 더 묻지 않는다. SKILL.md 모드 5의 skip 절차를 따른다.
7. 세션을 넘어 재개하면 직전 단계의 check 하나로 시작한다.

## 정확성

1. 설명에 확신이 없으면 원문이나 WebSearch로 확인한다. 확인하지 못하면 `[불확실]`을 붙이고 그대로 말한다.
2. 개념이 논문에 나오는 위치(`p.N`, 식, Figure)와 설명 근거의 출처를 구분한다. 표기는 SKILL.md 절대 규칙 2를 따른다.

## 도구 (단계에 도움이 될 때만)

- **비유**: 사용자가 강한 분야에 빗댈 때는 비유가 깨지는 지점을 같은 단계에서 함께 말한다. 깨지는 지점이 없는 비유는 오개념을 심는다.
- **기호표**: 수식을 다루면 먼저 기호 / 의미 / shape / 처음 등장 위치 표를 만든다. 논문마다 표기가 다르면 개념 노트의 표준 표기와 대응시킨다.
- **코드 앵커**: 공식 repo가 있으면 식과 코드 줄을 짝짓는다. 메커니즘이 작으면 `concepts/toy/<concept-slug>/`에 CPU로 도는 toy 스크립트를 만든다. 논문에 없는 구현 디테일을 찾으면 개념 노트 증거 로그의 메모에 적고, 비판과 관련 있으면 critique 노트의 Claude 피드백에도 적는다.
- **부모 논문**: 지금 단계에 필요한 섹션만 인용한다.

## 계획은 바뀐다

처음 계획은 스케치일 뿐이다. 가르치는 중 드러난 실제 이해가 다르면 순서를 고친다. 빠진 기초는 한 턴에 몰아 설명하지 않고 같은 속도로 한 단계씩 쌓는다. learn에서는 별도의 지도 산출물을 만들지 않는다.

## 종료

1. 논문에서 시작한 learn은 개념 check와 논문 앵커 check로 끝낸다. 논문 앵커 check는 해당 문단이나 식을 다시 읽게 하고 무슨 말인지 묻는 것이다. 가능하면 한 문항으로 합친다.
2. 논문 없이 시작한 learn은 개념 check와 다른 상황에 적용하는 check 하나로 끝낸다.
3. 개념 check 통과를 critique Phase 1 항목 통과로 치지 않는다. 다만 대화에서 실제 답을 보여준 항목은 Phase 1에서 다시 묻지 않는다.

## 기록

1. 응답마다 `learn_next`와 증거 로그(맥락 `learn`)를 갱신한다. 세션이 끊겨도 이어갈 수 있게 하기 위함이다.
2. skip·피로·종료 절차와 남은 `detour` 정리는 SKILL.md 모드 5와 "노트 상태와 재개"를 따른다. skip은 `skipped`(`learn_next`를 비움), 피로는 `paused`(`learn_next`를 남김)다.
3. 중단 요청이면 두 노트를 저장하고 바로 멈춘다. 마지막 check나 요약을 요구하지 않는다.
4. `status` 승급과 강등은 `templates/concept.md` 머리 주석의 상태 규칙을 따른다.
